ChromaDB — How Vector Search Works

Storing Knowledge

  • "Section 80C allows ₹1.5L deduction" → embedding model → [0.12, -0.54, 0.88 ... 768 numbers] → saved in ChromaDB

Searching at Query Time

  • User asks "how to save tax?" → embedding → compare mathematically to all stored vectors → return top 2 most similar chunks

🧾 TaxPlannerPage.jsx — Tax Formulas

Old Tax Regime

Taxable = Income − Deductions − ₹50,000 (standard deduction)
SlabTax Rate
₹0 to ₹2.5 Lakh0%
₹2.5L to ₹5L5%

📈 InvestmentPage.jsx — SIP & Lumpsum

SIP (Monthly Investment) Formula

FV = P × [((1 + r)^n − 1) / r] × (1 + r)

P

Monthly investment amount (e.g. ₹5,000)

r

Monthly interest rate = Annual% ÷ 12 ÷ 100 (e.g. 12% → 0.01)

n

Total months = Years × 12 (e.g. 10 years → 120)

Example: ₹5,000/month, 12%/year, 10 years → Future Value = ₹11,61,695

Lumpsum (One-Time Investment) Formula

FV = Amount × (1 + Rate/100)^Years

Example: ₹1,00,000, 12%/year, 10 years → Future Value = ₹3,10,585

🏦 EMICalculatorPage.jsx — Loan EMI Formula
EMI = P × r × (1 + r)^n / [(1 + r)^n − 1]

P

Principal loan amount (₹)

r

Monthly rate = Annual% ÷ 12 ÷ 100

n

Tenure in months = Years × 12

Example: ₹50L loan, 8.5% rate, 20 years → EMI = ~₹43,391/month

📐 State Management — How Pages Communicate

The app uses simple React useState hooks. There is no Redux or Context API. Here's how data flows:

// App.jsx holds the global navigation state:
const [activePage, setActivePage] = useState('chat')

// Sidebar receives setActivePage as a prop → calls it on button click
<Sidebar setActivePage={setActivePage} />

// App renders the correct page:
switch (activePage) {
  case 'chat':  return <ChatPage />
  case 'tax':   return <TaxPlannerPage />
  // etc.
}

⚠️ Limitation: Each page's own state (chat messages, goal amounts) is lost when you switch pages. Fix: lift state up to App.jsx or use React Context.
